# Workers — панель управления Firebase

Сайт команды: список участников, уровни, аватары, значки, анимации. **Данные редактируются через \`admin.html\`**, автоматически синхронизируются с Firebase Firestore. Старые TXT оставлены для миграции и резервного отображения.

## Запуск

1. В Firebase Console открой проект **workers-66fd8**.
2. В **Build → Authentication → Sign-in method** включи **Email/Password**. Создай свой аккаунт во вкладке Users и подтверди его почту. Открытую регистрацию на сайте мы не включаем.
3. В **Build → Firestore Database** создай базу (Production mode).
4. Открой опубликованный сайт **/admin.html**. Войди в Firebase Auth. Внизу блока будет показан **Firebase UID**.
5. В Firestore → Rules скопируй содержимое **firestore.rules**, замени \`PASTE_YOUR_FIREBASE_AUTH_UID_HERE\` на свой UID и нажми **Publish**.
6. Вернись в админку и нажми **Проверить доступ** (письмо должно быть подтверждено).
7. Нажми **Импорт TXT** один раз: он перенесёт Workers/Crafters.txt и Class/List.txt в Firestore, включит динамические данные и сохранит прежнее содержимое.
8. Далее редактируй участников, уровни и настройки **только в админке**. Новые записи сразу появляются на публичном сайте без коммитов GitHub.

## Структура Firestore
- \`workers/{id}\`: id, name, user, class, job, xp, photo, badge, badge_2, badge_3, color, teg, nameColor, outline, range.
- \`levels/{order}\`: order, name, oil, color, teg, advantages (массив строк), rang, outline.
- \`meta/site\`: title, subtitle, maintenance, maintenanceText, firebaseEnabled.

Для изображений подходят относительные пути из GitHub (например \`Image/icon_1.jpg\`) и прямые ссылки https://...; загрузка новых изображений в Firebase Storage пока не реализована.

**Важно:** Firebase Web API key не является серверным секретом. Безопасность держится на опубликованных правилах Firestore и проверке UID/emailVerified. Не заменяй правила на \`allow write: if true\`. Никогда не размещай сервисные ключи Firebase Admin SDK в публичном репозитории.

**Резервное поведение:** пока \`firebaseEnabled\` не включён, сайт отображает данные из TXT. \`Импорт TXT\` перезаписывает текущие записи в Firestore; не нажимай его повторно, если уже вручную изменил команду, иначе эти изменения потеряются.

## WORKERS 2.0 — участники, аккаунты, рейтинг, награды

Добавлены:
- \`account.html\` — вход выданным администратором аккаунтом, восстановление пароля, личный кабинет и редактирование имени/био.
- \`accounts-admin.html\` — выдача аккаунтов, очков, ролей и достижений.
- \`profiles/{uid}\` — публичный профиль (имя, био, роль, очки, активность, награды).
- \`achievements/{id}\` — каталог достижений.
- Публичные лидерборд и витрина достижений.

**Безопасность:** пользователи не могут самостоятельно увеличивать очки или выдавать себе награды. Эти действия доступны только владельцу через Cloud Functions (Firebase Admin SDK). Клиентская регистрация отключена: аккаунты создаёт владелец. Для пользователей с временным паролем рекомендуется восстановление пароля по email сразу после первого входа.

### Обязательная настройка Firebase
1. В Firebase Console включи **Authentication → Email/Password**.
2. В Firebase Authentication создай аккаунт владельца и подтверди его email.
3. В \`firestore.rules\` замени \`PASTE_YOUR_FIREBASE_AUTH_UID_HERE\` на **UID владельца**. Опубликуй правила (через консоль или CLI).
4. Для функций нужен Firebase-проект с поддержкой Cloud Functions (обычно план **Blaze**, биллинг может взиматься). Установи Firebase CLI и запусти \`firebase login\`, \`firebase use workers-66fd8\`.
5. Укажи UID владельца для серверной проверки, например в \`functions/.env\`:
   \`WORKERS_OWNER_UID=ТВОЙ_UID\`
   Этот UID должен совпадать с UID в правилах. Файл \`functions/.env\` не содержит секретов, но лучше не коммитить его.
6. В корне проекта: \`firebase deploy --only firestore:rules,functions\`.
7. После успешного деплоя открой \`admin.html\`, затем \`accounts-admin.html\`.

**Важно:** коммит файлов в GitHub **не разворачивает Cloud Functions автоматически**. До их публикации кнопки создания аккаунтов и управления наградами будут возвращать ошибку \`functions/not-found\`.

**Приватность:** данные \`profiles\` публичны для рейтинга. Не храни там email, пароли, телефоны или приватные сведения. Пароли никогда не сохраняются в Firestore. Для производственной системы с большим числом участников рекомендуется вынести публичный рейтинг в отдельную коллекцию и ограничить объём публичных данных.
